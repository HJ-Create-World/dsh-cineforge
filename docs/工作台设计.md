# CineForge 视频创作工作台 · 设计

> 定位：**确认与微调**的台子，不是从零创作的画布。创作判断由导演技能完成，工作台让人在最低成本处拍板。
> 与对话内使用共用同一份 `project.json`（分镜 JSON + 阶段 + 设计 spec + 素材清单），不产生两套事实。

## 1. 为什么把工作台前移

上游 video-shotcraft 的 Motion Workbench 是「**成片交付后**的剪映式多轨微调台」——很专业，但普通用户那时已经来不及改方向了。CineForge 面向的是「用户有个 idea，但不专业」的场景，最需要看清的是**开渲之前要拍什么**。所以工作台的主战场前移到阶段 0–5（简报 / 文案 / 分镜 / 动效选型），交付后的多轨微调仍保留为次要面板。

### A · Idea 面板

| 控件 | 行为 |
|---|---|
| 一句话 idea | 输入框；失焦后导演技能自动扩写成简报草稿，不覆盖用户原文 |
| 平台下拉 | 选 B站 / 抖音 / 小红书 / 视频号 / YouTube → **自动锁定画幅与推荐时长**，并刷新安全区提示 |
| 画幅 | 只读显示（9:16 / 16:9 / 3:4）；改动会回到阶段 0 并重算 |
| 文案 | 钩子 / 正文 / CTA / 标题 / 话题标签，逐项可编辑；字卡与 outro 重复时给出警告（P4） |
| 模式 | 共同创作（默认，保留分镜确认门）/ 自主自由创作（跳过确认门） |
| 数据口径 | 敏感数据冻结开关，默认开 |

### B · 分镜板（主舞台）

- **镜头卡片流**：每镜一张卡，显示编号 / 时长 / 镜头卡名 / 一句话意图 / 能量 / 缩略静帧 / 2 个验收帧号。可拖拽重排、拉两端改时长、双击展开编辑。
- **能量曲线**：把 `energy-arc.json` 画成折线，直观看出是否「低开 → 交替 → 峰值」。连续两个高能量镜会标黄警告。
- **帧级时间轴**：显示品牌 hold、批量收尾静止、呼吸字卡、转场帧、SFX 钉帧。这些**从 SHOTS 派生**，不可单独编辑（唯一事实源）。
- **静帧预览**：点镜头卡显示该镜的 2 张验收静帧；未渲时显示 styleframe 或配方卡预览。
- **确认放行按钮**：唯一硬门。点击前分镜表以清单形式完整呈现；点击后阶段推进到 6，A 面板的画幅 / 平台 / 时长变只读。

### C · 镜头库

- 按 `category` 折叠（10 类），按 `energy` / `duration` / `tags` 过滤。
- 有 `preview_url` 的卡显示循环动效预览；无预览的显示定妆帧并标注「缺少预览」。
- 卡片悬停显示**已知坑**摘要（这是最该被人看到的信息）。
- 拖拽到分镜板即把 `card_id` / `card_style_key` / 参数表 / 参考实现路径写入该镜。
- 侧边常驻**审美准则速查**（27 条），排分镜时随手对照。

### D · 底部条

- 11 阶段进度条，当前阶段高亮；点击已完成阶段可回退（带确认）。
- 渲染进度、静帧验收结果、终检报告的 ✓/✗ 计数。
- 导出：MP4（带/无 BGM）、剪映工程、平台封面。
- 发布：dry-run → 确认弹窗（文案 / 平台 / 隐私 / **AI 生成内容标识：显式 + 隐式** / BGM 字体授权 / 极限词）→ 只跑一次 → requestId 查询入口。
- AI 标识：导出产物写入隐式元数据，平台侧勾选显式声明；未勾两项不得提交（见 §7 合规）。

## 3. 状态机与落盘

```
IDEA → BRIEF → SCRIPT → SPEC → MAPPING → STORYBOARD ─[确认门]→
ASSETS → BUILD → SOUND → QA → DELIVER ─[发布确认]→ PUBLISHED
```

```json
// project.json
{
  "schema": "cineforge/project/v1",
  "stage": "STORYBOARD",
  "storyboard": { /* cineforge/storyboard/v1 */ },
  "design_spec": { "palette": [], "motion_tokens_id": "energetic-bold" },
  "assets": [], "qa_report": null, "publish_receipts": []
}
```

对话内技能与工作台**读写同一个文件**。用户在对话里说「把第三镜换成 spotlight-hero-card」，工作台刷新即见；反之亦然。

## 4. 技术形态（DSH 插件实测形态）

**前提事实**：DSH 插件不是独立 manifest 文件，而是 profile 的**组合包（bundle）= 一个 npm 包**。声明全在 `package.json` 的 `dsh` 字段（`dsh.bundle.patch` / `dsh.client.platform` / `dsh.profile.bundles` / `engines.dsh`），加载靠 `cordis.patch.yml`（YAML 数组 `- id/name/config/insert/disabled`）。能力由 Cordis Loader 的 `apply(ctx)` 注册：`ctx.skills.register` / `ctx.tools` / `ctx.mcpManager`；客户端另设 `exports["./client"]` → `lib/client.js`，浏览器侧只做 `window.__ModuleLoader__.load({id, factory})`，由 Host 注入 `window.__DSH_BOOT__`。安装用 `dsh plugin --profile desktop add <spec>`。

> 注意：`apps/web` 的 Vite 构建不等于独立应用（只有 `dsh web` 注入 `window.__DSH_BOOT__`）。工作台应作为**插件自带静态产物**由宿主加载，不要另起一个替代服务器。

| 方式 | 落地 | 取舍 |
|---|---|---|
| **A · 原生侧栏面板（推荐一期）** | `ctx.slots.inject("sidebar.panellist", …)` 注册图标 + `ctx.slots.inject("main", …)` 注册 keyed slot React 组件，直接读写 `project.json`。实证 `PF/node_modules/dsh-hyperframes/lib/client.js:137, 2528-2529`（`docs/WORKBENCH.md`） | DSH 原生、体验一致、无需 iframe 桥；需按 DSH 客户端插件契约写 React，受宿主样式约束 |
| **B · 侧栏 iframe 页（备选一期）** | `ctx.sidebarRight.openTab("browser", {params:{url}})`（`dsh-client-ui-sidebar-browser/README.zh.md`）；Web 用 sandbox iframe、Desktop 用 Electron `<webview>`，接受 HTTP(S)/loopback | 前端可用任意 Vite 栈、与 DSH 解耦；但要跨 iframe 桥读写 `project.json`，受侧栏宽度限制，分镜板需响应式 |
| **C · 独立本地页（二期）** | 插件起本地 dev server（参考上游 `workbench/scripts/open.mjs`，端口错开 HyperFrames），浏览器打开完整工作台 | 布局自由度最高、可复用上游多轨编辑器；但要多进程管理，且不是「DSH 内」的形态 |

**决策**：一期优先 A（原生面板），B 作为不想写 React 时的退路；C 留到二期。HMR 走 `/plugins/events` SSE，需 `pnpm run dev:web` + watcher 同时运行；Electron 桌面端不走此路，改动需重启或刷新。

## 5. 与上游 Motion Workbench 的分工

| | 上游 Motion Workbench | CineForge 工作台 |
|---|---|---|
| 时机 | 成片交付**后** | 分镜放行**前**（主）+ 交付后（次） |
| 对象 | 已渲成的多轨 clip 工程 | 未渲的分镜 JSON |
| 能力 | 多轨剪辑 / 变速 / 属性面板 / 导出 | 简报 / 文案 / 分镜确认 / 选卡 / 终检 / 发布 |
| 用户 | 会剪辑的人 | 不专业、只有 idea 的人 |

两者不冲突：CineForge 在阶段 10 可把成片交给上游工作台做多轨微调（可选能力，按需链接）。

## 6. 明确不做的（YAGNI）

- 不做逐帧关键帧编辑器（HyperFrames / 上游工作台已有）。
- 不做素材拍摄 / 生成式视频（画面来自产品截图与代码绘制）。
- 不做账号体系、云端协作、多人实时。
- 不做「一键全自动发布」的承诺（公开动作必须人确认）。

## 7. 发布合规（《AI 生成合成内容标识办法》2025-09-01 施行）

| 项 | 落地 | 来源 |
|---|---|---|
| 显式标识 | 平台「AI 生成」声明开关 + 视频画面/描述显式标注 | [网信办办法](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)、[抖音落地公告](https://trust.douyin.com/article/4011788173291140) |
| 隐式标识 | 导出 MP4 写入元数据 / 水印字段，不依赖平台 | 同上 |
| 内容审核 | 对照 [网络短视频内容审核标准细则(2021)](https://www.nrta.gov.cn/art/2021/12/15/art_110_59299.html) | 广电总局 |
| 素材授权 | BGM / 字体商用授权逐项核对；Freesound SFX 逐文件 CC BY 署名 | 上游 `assets/audio/ATTRIBUTION.md` |
| 广告法 | 无「最 / 第一 / 国家级」等极限词 | — |
| 数据安全 | 无未授权客户 / 个人 / 内部 / 密钥 / 实时数据 | 阶段 9 终检 |

> 一期只做「导出成片 + 手动上传指引 + 标识元数据 + 确认弹窗」；`biliup`（MIT）做成**用户自装**投稿适配器，抖音 OpenAPI 需机构认证，不承诺直连。

## 8. 验收

- 分镜板任一改动即时反映到 `project.json`，且时间轴 / 字幕 / SFX 同步派生。
- 平台切换后画幅、时长、安全区提示三者一致。
- 确认门前，底部渲染按钮不可用（硬约束，不是灰色提示）。
- 发布确认弹窗必须逐项列出文案 / 平台 / 隐私 / **AI 生成内容标识（显式 + 隐式）** / BGM 字体授权 / 广告法极限词 / 数据安全；未勾 AI 标识两项不得提交；发布命令只触发一次，超时或 `status: unknown` 绝不重跑。
