# CineForge 视频创作工作台 · 设计 v3

> 一句话：工作台不是编辑器，是**拍板台**。它把「普通模型缺的那部分设计判断」变成看得见、改得动、签得了字的东西。
>
> 与对话内技能共用同一份 `project.json`，不产生两套事实。

- v1（2026-11-24）定下：定位、四区布局、状态机、技术形态 A/B/C 与「一期优先 A」。
- v2（2026-11-25）补齐：设计动机、**动态分镜（animatic）**、对话协作时序、面板交互状态、并发写冲突、一期交付切片与可勾选验收。
- **v3（2026-11-25）按用户五条新需求扩写**：① AI 全流程自动 + 逐处可改；② 关键阶段人工拍板 + GOAL 连续模式（可随时打断）；③ 输入源三态（文字 / 视频 / 模板）；④ 流程存为可复用模板；⑤ 明暗双主题 + 主题可扩展。全部能力都已在本机用真实素材验证或明确标注为「未验证」，见 §2。

## 0. 五条设计原则

| # | 原则 | 落到界面上是什么 |
|---|---|---|
| 1 | **最便宜的拍板点** | 每个决定都放在「还能改」的时刻。分镜放行前能改方向，放行后只能改像素。 |
| 2 | **用眼睛和耳朵决策，不用 JSON** | 用户不看分镜表，看播放。所有关键判断都配一个能播的预览。 |
| 3 | **工作台不生产内容，只生产决定** | 生成（写文案、选卡、改分镜）永远回对话里由导演技能完成；工作台只做「看、比、改参数、签字」。 |
| 4 | **唯一事实源** | `project.json` 是唯一可写的；时间轴、字幕轨、SFX 钉帧、能量曲线全是它的派生视图，不可单独编辑。 |
| 5 | **判例而非评分** | 27 条审美准则变成可勾选的检查项与红色徽标，不给「设计感 82 分」这种假指标。 |

## 1. 用户会在哪里做错（设计动机）

用户原话是「视频制作这一块我也不专业」。不专业的本质不是不会点按钮，是**不知道该在什么时候否定什么**。下面六条是这类用户最高频的翻车点，原来工作台的每个区块都对应其中一条；v3 新增的五条需求，本质上是把这六条从「事后补救」提前到「事前约束」。

## 2. 五条新需求的落地判断（先说能做 / 不能做）

这一节是对用户 5 个问题的直接回答。每条都给：**能做到什么程度**、**代价**、**当前实证状态**。不做能力吹嘘。

### 2.1 需求 1：AI 全流程自动生成，且各部分可改

**能。** 但要把「自动化」和「可控性」拆成两个正交维度，否则会变成「要么全自动要么全手动」的二选一。

| 维度 | 设计 |
|---|---|
| AI 自主 | 11 阶段流水线（`cineforge-director` 技能已实现），每一阶段都有确定产物：分镜 JSON、动效映射表、project.json、渲染命令。模型只需按阶段产出结构化文件。 |
| 用户可改 | **字段级锁定**。每个镜头、每个文案段、每条动效参数都有 `locked: true`。AI 重跑时跳过锁定字段，未锁定字段按当前上下文重生成。 |
| 改完的连锁 | 改分镜 → 自动重算时长前缀和与能量曲线 → 需要重新放行（若已放行）→ 已生成的 animatic/renders 标记失效。 |
| 粒度 | 三级：**工程级**（重跑整条流水线）/ **镜头级**（只重做某几镜）/ **字段级**（只改某一句话或某个参数）。 |

**落盘形状**（扩 `cineforge/storyboard/v1`，不改语义）：

```json
{
  "id": "s03",
  "card_id": "blur-slide",
  "locked": ["card_id", "duration_f", "props.blur"],   // 锁定字段路径，AI 不覆盖
  "user_edited": ["intent", "props.blur"],              // 用户改过的字段，界面上加琥珀左边线
  "origin": "ai"                                        // ai | user | template | reference
}
```

- `locked` 是**路径数组**而不是布尔值：锁一个镜头的「卡名」但不锁它的「文案」是常见诉求。
- `user_edited` 只影响视觉标记与「AI 重跑时是否提示」，不阻止 AI 覆盖（锁才是阻止）。
- 锁定写在 `project.json` 里，对话里的技能与工作台共用同一份，不存在两套锁。

**实证状态**：锁定语义与 `user_edited` 标记已落到 `knowledge/storyboard.schema.json`（本轮改）；AI 重跑遵守锁定是技能层 `SKILL.md` 的硬规则（已写）。**尚未做**：字段级 diff 提示（改 A 影响 B 时的提示），列在 §14 P1。

### 2.2 需求 2：关键阶段人工拍板 + GOAL 模式 + 随时打断

**能，而且这是本设计的主轴之一。** 关键是区分两种门：

| 门 | 例子 | 行为 |
|---|---|---|
| **硬门（hard gate）** | 分镜确认、发布确认 | 不点不前进。渲染按钮禁用。这是唯一能拦住「自动跑飞」的机制。 |
| **软门（soft gate）** | 文案确认、视觉方向、静帧验收 | 默认倒计时自动通过（可关），但通过后仍可回退。界面上是「已自动通过 · 可回退」，不是「已完成」。 |

用户原话「关键阶段，由用户排版决定再进入下一阶段」= 硬门；「如果前面的阶段有内容需要修改，又能支持用户调整部分内容」= 软门 + 回退；「增加 goal 模式」= 顶部 AUTO 开关：

```
GOAL 模式（AUTO）运行时序
  ① 简报五问 + 平台 + 时长 + 文案 —— 一次性确认（唯一必要的启动门）
  ② 开跑：SPEC → MAPPING → STORYBOARD 全自动，只在硬门前停
  ③ 硬门前挂起：写 .local/goal-state.json { stage, waiting_for: "storyboard_approve", since }
  ④ 用户拍板 / 或改任意字段 → 从该阶段继续（不是从头重跑）
  ⑤ 没有打断就一路跑到 DELIVER，把成片路径写到 goal-state.json
  ⑥ 用户随时可点「打断」：立即停在最近的安全点（阶段边界），已完成产物保留
```

- **打断不是取消**：已完成的镜头渲染保留，恢复时从断点继续。这要求在 `project.json` 里记录每镜的 `render_status: pending|done|stale`。
- **GOAL 模式不会跳过硬门**。用户要求「用户前期确认好全部信息后，开始制作作品直到结束」——前期确认的就是简报与文案，分镜确认仍是一次硬门（可配置为软门，但默认硬）。
- **安全点定义**：只在阶段边界与单镜渲染完成时落盘，反对「任意时刻可打断」的夸张承诺（渲染进程被杀会留下半个文件，需要清理）。

**实证状态**：AUTO 开关与「把关点」列表已进设计稿；`goal-state.json` 形状与「安全点」定义在 §5.4。**尚未实现**：断点续跑的执行器（列 §14 0.5.0 骨架之后）。

### 2.3 需求 3：导入参考视频，复刻风格 / 内容 / 片段

**能，且已在本机跑通**。这是五条里唯一有完整实证的一条，因为它是纯本地 ffmpeg 计算，不依赖任何模型或云服务。

| 能力 | 实现 | 实证 |
|---|---|---|
| 切分镜 | 帧差法（`fps=4, scale=48:H, gray`，逐帧平均绝对差，`thr=max(mean*2,5)`，0.5s 内合并） | demo 20s 片：6 镜，切点 0.1/3.2/6.0/10.0/17.0，与真实边界（0/3/6/10/14/17/20）吻合 5/6 |
| 关键帧 | 每镜 15% / 50% / 85% 三帧，360px 宽 | 18 张 jpg + contact-sheet.png（1800×534） |
| 调色板 | kmeans(10) on 2fps/80×80 RGB 全像素 | 主色 `#10151b` 43.5%，与 design_spec 一致 |
| 强调色 | 色相桶 H≈35°、S≥0.40、L 0.30–0.85 | `#ca8d39`，与真值 `#D3923C` 高度吻合 |
| 明暗结构 | 亮度 L<60 / <170 / 其余 三档 | 暗 95.4% / 中 3.7% / 亮 0.9% |
| 运动强度 | 8fps/48×H 灰度帧差 p50/p90/p99 + static_ratio | p90 2.65、静态占比 87.4% |
| 节奏 | 谐波求和法估计 BPM | **130 BPM**（真值 129），旧法给 95.2 已废弃 |

**不能做的（必须说清）**：

- 不能「复制内容」。原片里的人和产品不会被搬过来，只取风格参数（调色板 / 明暗 / 运动强度 / 节奏）。
- 不能「1:1 复刻动效」。帧差只能告诉你「这里动得快」，不能反解出「这是 blur-slide 的 mid→mid-high 缓动」。要 1:1 复刻必须看源码或人工标注 —— 这条列在 §13 YAGNI。
- 不能分析「某个片段」的具体内容语义（讲了什么），只能给出该片段的时长、运动量、主色。语义理解仍需模型看图（关键帧拼图给模型看，这是可行的，见下条）。

**推荐的复刻流程**（人机分工，已写进 `cineforge-director` 技能）：

1. 本机 ffmpeg 切分 → 关键帧拼图 + 指纹 JSON（不上传原片）；
2. 把**拼图 + 指纹**交给模型，模型只能看这些静态证据来推断「这是什么类型的镜头、大概用了什么动效」；
3. 模型输出的每个推断都必须标 `confidence: high|med|low` 与依据；
4. 用户在工作台「复刻什么」里勾选（风格 / 结构 / 某个片段），未勾选的不写进新工程。

### 2.4 需求 4：把制作流程存为模板

**能，但要先把「模板」和「工程」的边界划死**，否则模板会变成「内容也一起复制」的灾难。

| 层 | 进模板 | 不进模板 |
|---|---|---|
| 视觉风格 | 调色板、字体栈、动效 token、安全区规则 | 具体文案、产品名、logo 图 |
| 分镜结构 | 镜头数量、时长配比、能量曲线、卡片 id 序列 | 每镜的具体文字内容 |
| 动效配方 | card_style_key、primitive、缓动、overshoot | 与具体 DOM 结构相关的选择器 |
| 声音设计 | BPM、SFX 类型与相对拍点位置 | 具体音频文件路径 |
| 文案骨架 | 段落数量与功能（钩子/正文/CTA 的句式） | 具体字句 |

```json
{
  "schema": "cineforge/template/v1",
  "id": "ink-press",
  "name": "Ink Press",
  "from_project": "demo-01",
  "layers": ["style", "structure", "motion", "sound"],
  "style": { "palette": {}, "fonts": {}, "motion_tokens_id": "energetic-bold" },
  "structure": { "shot_count": 6, "durations": [98, 83, 120, 128, 83, 90], "energy_arc": "launch" },
  "motion": { "cards": ["brand-ink-open", "blur-slide", "..."] },
  "sound": { "bpm": 130, "sfx_pattern": "tick-on-cut" },
  "slots": ["product_name", "headline", "cta"]     // 新建工程时必须填的空位
}
```

- **模板是「怎么拍」，不是「拍什么」**。`slots` 明确列出新建时必须替换的内容空位。
- 模板从已完成的工程提取（`scripts/extract-template.mjs`，待写），也可手写。
- 复用时可只取若干层（设计稿「复用哪几层」多选）。

### 2.5 需求 5：明暗双主题 + 可扩展

**已做到**。做法不是「准备两套 CSS」，而是**一层 token 抽象**：

```css
:root{ --cf-ground:#0B0E14; --cf-ink:#F4F1EA; --cf-accent:#D3923C; ... }
[data-theme="light"]{ --cf-ground:#F7F5F0; --cf-ink:#1A1D22; --cf-accent:#9A5B12; ... }
[data-theme="hc"]{ ... }   /* 未来：高对比 / 色弱友好 / 品牌皮肤，只覆盖同名 token */
```

- 组件只用 `var(--cf-*)`，**不写死任何颜色**。新增主题 = 新增一组同名 token，不动任何组件代码。
- 已做对比度审计：暗色 4 个文本层级、亮色 3 个文本层级全部 ≥ 4.5:1（含 accent 对 ground 7.31/4.97）。
- 主题选择存 `localStorage.cineforge:wb:theme`，跟随后台系统偏好作为初始值（`prefers-color-scheme`）。
- 主题是**工作台自身的显示偏好**，不写进 `project.json`（否则换主题会 rev+1，无意义）。

**扩展点**：`themes/<id>.json` 只放 token 覆盖，插件启动时读目录生成切换列表；第三方皮肤只需加一个 JSON 文件。

## 3. 输入源三态：文字 / 视频 / 模板

v2 只假设「用户打一句话」。v3 把它扩成三种入口，三者最终都归一成同一份 `brief` + `design_spec` + `shots`，因此下游编译链零改动。

| 输入源 | 用户给什么 | 系统产出什么 | 归一化后的差异 |
|---|---|---|---|
| 文字 | 一句 idea | 五问 + 文案 + 分镜 | 无，v2 原路径 |
| 视频 | 一个参考片文件 | 切分 + 关键帧 + 风格指纹 | `design_spec` 预填、`shots` 结构可参考、`origin: reference` |
| 模板 | 一个 template id | 风格/结构/动效/声音四层 | `design_spec` 与 `shots` 骨架预填、`origin: template` |

**关键约束**：

- 三种输入源可以**叠加**（先选模板定骨架，再给参考片定风格，最后写文字定内容）。设计稿里它们是三个 tab，但语义是「可叠加的三层」，不是互斥的单选。
- 叠加冲突的处理顺序：**文字 > 视频 > 模板**。用户明确写的文案永远最高优先级；参考片只覆盖视觉与节奏；模板只填空。
- 参考片与模板都必须经过「复刻什么 / 复用哪几层」的显式选择，不默认全选。

### 3.1 视频输入的处理链路（已实证）

```
参考片.mp4
   ↓ analyze-reference.mjs（本机 ffmpeg，不上传）
   ├─ meta       1080×1920 / 30fps / 20.0s / 有音轨
   ├─ shots[]    6 镜 + 每镜 from/to/duration_f
   ├─ keyframes  18 张（每镜 15% / 50% / 85%）
   └─ contact-sheet.png   给模型看的证据图
   ↓ style-fingerprint.mjs（本机 ffmpeg + 纯 JS 计算）
   ├─ palette[]  6 色 + 占比
   ├─ tone       dark/mid/light 占比
   ├─ motion     p50/p90/p99 + static_ratio
   └─ audio      onsets / median_ioi / bpm_est(谐波求和) / rms
   ↓ 模型只看「拼图 + 指纹」推断镜头类型与动效
   ↓ 用户勾选「复刻什么」
新建工程（origin: reference）
```

**为什么不让模型直接看视频**：本机没有视频理解模型通道；且原片可能含客户未公开内容，本机分析 + 只把静态拼图交给模型是隐私上更保守的做法。

**实测样本**（`out/cineforge-demo-01/renders/cineforge-demo-01.mp4`）：

| 项 | 值 |
|---|---|
| 分辨率 / 帧率 / 时长 | 1080×1920 / 30fps / 20.0s |
| 切分 | 6 镜：0–3.25 / 3.25–6 / 6–10 / 10–14.25 / 14.25–17 / 17–20 |
| 主色 | `#10151b` 43.5% / `#080e12` 23.7% / `#0b1116` 21.5% |
| 强调色 | `#ca8d39`（真值 `#D3923C`） |
| 明暗 | 暗 95.4% / 中 3.7% / 亮 0.9% |
| 运动 | p90 2.65 / 静态占比 87.4% |
| 节奏 | 130 BPM（真值 129）/ 77 个重音 / 中位间隔 0.16s |

### 3.2 已知失败与不可用方案（避免重复踩坑）

- **ffmpeg `scdet` 与 `select=gt(scene,…)` 在本类片子上 0 命中**：大面积静态 + 缓动转场导致场景分数极低，阈值降到 0.08 仍空。必须用自研帧差法。
- **谱通量峰值法估 BPM 不可靠**：结果随阈值剧烈变化（2.2×均值→95.2，1.5/3.0/4.0→空），已替换为谐波求和法。
- **单周期自相关会锁倍频**：给出 192.9 而真值 129。必须叠加 2x/3x/4x 谐波。
- **hyperframes `reverse` 不能当本地复刻通道**：`plugin-cli.mjs reverse --help` 只有 `start` 子命令，且依赖 HeyGen 云端账号（免费账号会被拦），与「本机离线分析」目标冲突。

### 3.3 视频输入在界面上的样子

见设计稿 `docs/design/mockups/workbench.html?tab=video`：文件 chip → 切分拼图（角标「已切 6 镜」）→ 指纹四行（调色板 / 明暗 / 运动 / 节奏）→「复刻什么」多选 → 隐私提示。截图 `workbench.png`。

### 3.4 模板：从哪来、存哪、怎么用

- 存：`templates/<id>/template.json` + 可选 `poster.jpg`（模板封面）。
- 来源三条：① 从已完成工程提取（推荐）；② 内置 4 个（Ink Press / Terminal Dark / Launch Poster / Editorial Calm，其中 Ink Press 来自上游 template/ 的真实成片参数）；③ 用户手写 JSON。
- 用：新建工程时 `template_id` 写入 `project.json`，并按其 `layers` 预填对应字段；`slots` 逐项要求用户填写，未填不能进 STORYBOARD。
- 界面：A 区「输入源 · 模板」+ C 区「模板」tab（含「内容不入模板」提示）。

## 4. AI 自主度模型（需求 1 的核心）

### 4.1 三级自主度

| 级别 | 名称 | AI 做什么 | 用户做什么 | 何时用 |
|---|---|---|---|---|
| L0 | 手动 | 只做单点操作（改一句文案、换个卡） | 全部决策 | 已熟练用户 |
| L1 | 共创（默认） | 每阶段出方案，硬门前停 | 每阶段拍板或改 | 首次做片 |
| L2 | GOAL / AUTO | 一路跑到成片，只在硬门停 | 前期确认一次 + 随时可打断 | 已经知道要什么 |

自主度不是全局开关，**是每阶段的属性**：可以在 SPEC 阶段用 L2、在 STORYBOARD 阶段降回 L1。设计稿顶栏的 `AUTO` 徽标是「当前阶段自主度」的显示，不是全局模式。

### 4.2 锁定（lock）语义

- 锁的粒度是**字段路径**：`["card_id", "duration_f", "props.blur"]`。
- 锁只对 AI 生效，不限制用户自己改；用户改锁定字段时提示「此字段已锁，AI 不会再动它」。
- 「锁整镜」= 锁该镜所有字段，用一个快捷按钮写入 `locked: ["*"]`。
- 换卡时：新卡的 `card_id` 与 `props` 若与旧锁的路径冲突，提示「这张卡的部分参数被锁，是否解锁后再换」。
- 锁信息的持久化在 `project.json`，工作台与对话技能共享；AI 重跑前必须读 `locked`。

### 4.3 局部重跑的三种粒度

```
工程级：整条流水线按当前 brief 重跑         → 全部产物失效
镜头级：只重做 S03                         → S03 的 animatic 段与渲染失效
字段级：只改 S03.props.blur                → 仅 S03 渲染失效
```

失效传播由 `project.json` 的 `stale` 标记驱动，不靠文件删除（删除会丢证据）。

## 5. 把关点与 GOAL 模式（需求 2 的核心）

### 5.1 关卡清单

| # | 关卡 | 类型 | 默认 | 可配置 |
|---|---|---|---|---|
| 1 | 简报确认（五问 + 平台 + 时长） | 硬门（GOAL 模式的启动门） | 人工 | 否 |
| 2 | 文案确认 | 软门 | 自动通过（有 30s 倒计时提示） | 是 |
| 3 | 视觉方向（design_spec） | 软门 | 自动通过 | 是 |
| 4 | **分镜确认** | **硬门** | 人工 | 仅 GOAL 模式可降为软门（需手写确认语） |
| 5 | 静帧验收 | 软门 | 自动通过（有失败项则升为硬门） | 是 |
| 6 | 终检（QA） | 硬门（有 error 时） | 人工 | 否 |
| 7 | 发布 | 硬门 | 人工 | 否 |

### 5.2 软门的行为细节

- 软门通过后，界面显示「已自动通过 · 可回退」，**不是**「已完成」。
- 软门通过不删除任何中间产物，回退时代价小。
- 软门倒计时只在 GOAL 模式下启用；共创模式下软门也需要用户点一下（但不阻塞，可以「跳过」）。

### 5.3 GOAL 模式的运行契约

```json
// .local/goal-state.json
{
  "schema": "cineforge/goal-state/v1",
  "project": "demo-01",
  "started_at": "2026-11-25T16:20:00+08:00",
  "stage": "STORYBOARD",
  "status": "waiting",              // running | waiting | interrupted | done | failed
  "waiting_for": "storyboard_approve",
  "safe_point": { "stage": "STORYBOARD", "shot_index": null, "render_done": [] },
  "completed_stages": ["SPEC", "MAPPING"],
  "interrupt_requested": false,
  "last_heartbeat": "2026-11-25T16:21:12+08:00"
}
```

- 每次阶段边界写一次；每镜渲染完成后更新 `safe_point.render_done`。
- 「打断」按钮写 `interrupt_requested: true`，执行器在下一个安全点退出并置 `status: interrupted`。
- 恢复：读 `goal-state.json`，从 `safe_point` 继续，不重跑已完成且未 stale 的产物。
- 心跳用于判断「进程是否还活着」：超过 3 分钟无心跳且 status=running → 界面显示「可能已中断」，不自动重启。

### 5.4 为什么不做「任意时刻可打断」

当前阶段的设计里，一次渲染是一次 ffmpeg/puppeteer 调用，中途 kill 会留下不完整的 mp4 与半写的 index.html。诚实的做法是：**打断请求被记录，执行在最近的安全点生效**，最长等一个镜头（通常 2–5 秒）。这与「随时打断」在体验上几乎无差别，但避免了脏状态。

## 6. 动态分镜（animatic）：本设计的核心

### 6.1 是什么

把已确认的分镜表编译成一支**低分辨率、静帧驱动、但时间线与声音完全真实**的预览片：

- 画面：每镜用该镜的定妆帧 / 配方卡海报，按该镜的 `primitive` 加一层**运动近似**（推、拉、移、淡入）。
- 文字：真实字卡文案，真实字号与安全区。
- 转场：真实的 `transition_in/out` 与帧数。
- 声音：**真实 BGM、真实拍点、真实 SFX 位置**——这一条是它值钱的地方。
- 规格：540×960（9:16）/ 960×540（16:9），draft 质量，无水印。

### 6.2 为什么必须有

行业里动画和广告的标准流程是 **storyboard → animatic → final**，中间这一步就是用来「用最低成本发现节奏不对」的。上游 video-shotcraft 的 Motion Workbench 在**成片之后**才让你微调，那时候节奏问题已经烧进每一帧了。

对 CineForge 的用户来说，animatic 是唯一能在「还没开始逐镜实现」时感到对不对的东西：

- 只改分镜 JSON，不写一行动效代码；
- 时间线、拍点、字幕、SFX 全部来自同一份 SHOTS，改了立刻重编；
- 看完不满意，改的是**分镜**，不是像素。

### 6.3 怎么实现（复用现有编译链，不新写渲染器）

`scripts/compile-hf.mjs` 已经导出了 `{ compile, fill, normalizeShots, buildTweens, HF_CONFIG }`，时间线、音频、字幕、AIGC 元数据都在里面。animatic 只是给它加一个模式：

```
node scripts/compile-hf.mjs --project <project.json> --out out/<id> --animatic
```

- 每镜的 `buildTweens` 换成「单帧 + 缓动位移」的最小集合；
- 分辨率降到 540×960，`--quality draft`；
- 音频链路一字不改（这是它可信的原因）。
- 产物：`out/<id>/animatic/index.html` 与 `out/<id>/animatic/renders/animatic.mp4`。

### 6.4 它不承诺什么

- 不是最终画质，不能拿去发布；
- 动效只是近似，不能用来验收「动效做得好不好」；
- 真正的逐镜实现仍要走阶段 7（BUILD）与静帧验收。

| 字段 | 说明 |
|---|---|
| 编号 + 时长 | `S03 · 2.0s (60f)`；拉卡片右下角改时长，最小 15f |

1. 连续 ≥3 镜高能量 → 黄条「缺呼吸」；

## 8. 与对话的协作

### 8.1 三段式时序

```
① 对话开局（生成）
   用户: 「给 XX 产品做个 20 秒抖音片」
   导演技能: 五问 → 简报 → 文案 → 视觉方向 → 选卡 → 写 project.json（stage=STORYBOARD）
        ↓  同一份文件
② 工作台拍板（决策，不生成）
   用户打开 CineForge 面板 → 看 animatic → 改时长/换卡/改文案
   → 每次改动写回 project.json（rev+1）
   → 点「确认放行」→ stage=ASSETS
        ↓  同一份文件
③ 回对话执行（生成）
   「分镜已放行，继续」
   导演技能: 采集素材 → 逐镜实现 → 静帧验收 → 声音 → 终检 → 渲染
```

### 8.2 硬边界

| 事情 | 谁做 | 为什么 |
|---|---|---|
| 写文案 / 选卡 / 扩写 idea | **对话里的导演技能** | 需要模型判断，工作台没有生成能力 |
| 改参数 / 排序 / 改时长 / 签字 | **工作台** | 需要即时反馈与拖拽，对话里做不了 |
| 编译 / 渲染 / 终检 | **对话里的技能**（调脚本） | 长任务，要日志与重试 |
| 发布 | **人** | 公开动作必须人确认 |

### 8.3 「让导演继续」按钮的真实语义

实测：`ctx.get("conversation").input.for(actx)` 需要会话上下文（actx），而 **main 槽的组件拿不到 actx**（main 是全局 keyed 槽，不绑会话）。所以一期不承诺「一键代发消息」，只做：

- **复制指令**：把「分镜已放行，继续阶段 6」这类指令写进剪贴板，用户粘到输入框回车；
- 二期若要「填进草稿」，需把入口改成右侧栏会话 pane（有 `sessionId`），届时再评估。

> 这条是设计上的诚实边界：不假装能替用户按回车。

| 状态 | 触发 | 界面 |
|---|---|---|
| 空 · 无工程 | 工作区里没有 `projects/*/project.json` | 大空态：一段说明 + 「在对话里说出你的 idea」+ 复制示例话术按钮 |

## 10. 数据、并发与安全

### 10.1 project.json（在 v1 形状上扩两个字段）

```json
{
  "schema": "cineforge/project/v1",
  "rev": 12,
  "updated_at": "2026-11-25T07:30:00Z",
  "stage": "STORYBOARD",
  "project": { "id": "...", "platform": "douyin", "aspect": "9:16", "duration_s": 20 },
  "brief": { "audience": "", "action": "", "pitch": "", "evidence": "", "tone": "" },
  "design_spec": { "palette": {}, "motion_tokens_id": "energetic-bold" },
  "shots": [],
  "audio": {},
  "publish": {},
  "qa_report": null,
  "publish_receipts": []
}
```

`shots` 沿用 `cineforge/storyboard/v1` 的字段，不改语义（编译链不动）。

### 10.2 并发写：rev CAS

工作台是唯一写者（对话里的技能也走同一个写函数），所以只需要乐观锁：

```
POST /api/dsh-cineforge/project/save
{ project: "demo-01", baseRev: 12, patch: {...} }
→ 200 { rev: 13, saved_at }
→ 409 { currentRev: 14, current: {...}, mine: {...} }   // 客户端进「冲突」态
```

- 写前把旧文件复制到 `.local/backup/project-<rev>-<ts>.json`（保留最近 20 份）。
- 写用「临时文件 + rename」，避免半截文件。
- **绝不** 服务端自动 merge：分镜是数组，自动 merge 会静默丢镜头。

### 10.3 路径安全

- 客户端只传 `project` 名，形如 `^[a-z0-9][a-z0-9-]{0,63}$`，不传绝对路径。
- 服务端用 `ctx.get("workspaceRegistry").list()` 取工作区根，拼 `projects/<name>/project.json`，`path.resolve` 后必须仍在根内。
- 所有写操作限制在该工程目录内；渲染产物只读。

## 11. 技术形态与实现要点

| 方式 | 落地 | 取舍 |
|---|---|---|
| **A · 原生面板（一期）** | `exports["./client"]` + `dsh.client = { platform: "web", inject: ["slots"] }`；`window.__ModuleLoader__.load({ id, factory })` 注册 React 组件；`ctx.slots.inject("sidebar.panellist")` 图标 + `ctx.slots.inject("main")` 面板 | DSH 原生、无 iframe 桥、体验一致；受宿主样式与槽位契约约束 |
| B · 侧栏 iframe 页 | `ctx.sidebarRight.openTab("browser", { params: { url } })` | 前端自由，但要跨 iframe 桥、宽度受限 |
| C · 独立本地页 | 插件起本地 server | 布局自由，但不是「DSH 内」形态，多进程管理 |

**决策不变：一期做 A。**

实现要点（都已在本机源码实证，逐条是坑）：

1. `sidebar.panellist` 注册的 `id` 必须与 `main` 槽的 `key` **完全一致**，否则点击抛 `main panel "x" is not registered`。
2. 客户端只 `require("react")`，**手写零依赖 CJS-in-factory**；本机没有 esbuild/vite 可打包。
3. 样式全部 scope 在 `.cfw`，一次性注入 `<style id="dsh-cineforge-styles">`。
4. 服务端路由走 `ctx.inject(["webServer"], child => ...)` 子作用域 + `effect` 清理 + 重复注册 try/catch；**绝不**把 `tools`/`connection`/`webServer` 写进插件顶层 `inject`（会重演 0.3.1 的 PENDING 故障）。
5. 路由做 same-origin 校验，跨域直接 403。
6. 返回对话：`ctx.get("layout").selectPanel(null)`（可选服务，取不到时隐藏按钮，不报错）。
7. 所有 disposer 挂 `ctx.effect` 与 `ctx.on("dispose")` 双保险。
8. 安装后与其他插件零耦合：不改 `cordis.patch.yml` 的 insert 列表，不写全局 CSS，不改宿主主题。

## 12. 阶段推进与回退

```
IDEA → BRIEF → SCRIPT → SPEC → MAPPING → STORYBOARD ─[确认门]→
ASSETS → BUILD → SOUND → QA → DELIVER ─[发布确认]→ PUBLISHED
```

| 改动 | 回退到 | 失效产物 |
|---|---|---|
| 平台 / 画幅 / 时长 | IDEA | 分镜时长全重算、animatic、renders |
| 文案 | SCRIPT | 字卡文本、animatic 字幕 |
| 分镜增删 / 换卡 | STORYBOARD | animatic、renders |
| 已放行后改分镜任一项 | STORYBOARD（重新放行） | animatic、renders、verify.json |
| 只改 `props`（同卡片） | BUILD | 仅该镜渲染与静帧 |

确认门前，D 区渲染按钮**不可用**（`disabled` 且不带 hover 提示，因为这不是可协商项）。

### 12.1 GOAL 模式下的阶段机

GOAL 模式不改变阶段顺序，只改变「谁按继续」：

- 每个阶段结束时写 `goal-state.json`，然后判断：本阶段是否为硬门？
- 是硬门 → `status: waiting`，等人；不是 → 自动进入下一阶段。
- 用户在任何时刻点「打断」→ 置 `interrupt_requested`，执行器在安全点停。
- 恢复时从 `safe_point.stage` 继续；`stale` 的产物重跑，未 stale 的跳过。

**不允许**：GOAL 模式自动通过分镜硬门（除非用户在启动时手写了「我确认跳过后续分镜确认」，且该行为记入 `goal-state.json.overrides`）。

### 12.2 回退在 GOAL 模式下的语义

回退会先置 `status: interrupted`，再回退阶段，再等用户重新启动 GOAL。**不自动重新开跑**——回退本身是用户的决定，重启也应当是。
